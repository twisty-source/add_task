# Система управления задачами (Task Manager)

Веб-приложение на **Django** с интерфейсом на **Bootstrap 4** для персонального планирования и контроля задач с разделением прав доступа.

Проект выполнен в рамках практической работы: [🔥 Самостоятельная работа 1 — Система управления задачами](https://практика.ркси.рф/task-1-sistema-upravleniya-zadachami.html).

---

## 🛠 Стек технологий

- **Язык**: Python 3.10+ / 3.12
- **Фреймворк**: Django 5.x
- **UI / Стили**: Bootstrap 4 (`django-bootstrap4`)
- **Статика**: WhiteNoise
- **WSGI-сервер**: Gunicorn
- **База данных**: SQLite (хранится в постоянном томе Docker)
- **Контейнеризация**: Docker & Docker Compose

## 🎯 Реализованный функционал

1. **Модель `Task`**:
   - `owner` — внешний ключ к пользователю `User` (каждая задача строго привязана к владельцу);
   - `title` — краткое название (до 200 символов);
   - `description` — подробное описание задачи;
   - `date_added` — автоматическая дата создания;
   - `due_date` — срок выполнения (дата и время с HTML5-виджетом `datetime-local`);
   - `priority` — приоритет: *Низкий*, *Обычный* (по умолчанию), *Высокий*;
   - `completed` — флаг выполнения задачи (`True`/`False`);
   - свойство `is_overdue` — определяет, просрочена ли невыполненная задача.

2. **Порядок сортировки в списке задач**:
   - Невыполненные задачи отображаются выше выполненных;
   - По приоритету: *Высокий* ⚡ &rarr; *Обычный* 📌 &rarr; *Низкий* 💤;
   - По сроку: ближайшие дедлайны отображаются первыми, задачи без срока — в конце;
   - По дате создания: новые задачи выше.

3. **Фильтры и поиск** (дополнительные возможности):
   - Вкладки фильтрации: **Все**, **Активные ⏳**, **Выполненные ✅**, **Просроченные ⚠️**;
   - Строка быстрого поиска по названию и описанию задачи.

4. **Безопасность и разграничение прав**:
   - Все страницы задач защищены декоратором `@login_required`;
   - Выборка задач выполняется исключительно для текущего пользователя: `Task.objects.filter(owner=request.user)`;
   - Проверка владельца: `get_object_or_404(Task, id=task_id, owner=request.user)`. Подбор чужого или несуществующего ID возвращает ошибку **404 Not Found**;
   - Создание задачи автоматически назначает `owner = request.user`;
   - Переключение статуса выполнения (`toggle`), подтверждённое удаление (`delete`) и выход из системы (`logout`) выполняются **только методом POST** с CSRF-токеном. Попытка удаления через GET не изменяет данные.

## 💻 Локальный запуск (для разработки)

1. Клонируйте проект и перейдите в папку `task_manager`:
   ```bash
   cd task_manager
   ```

2. Создайте и активируйте виртуальное окружение:
   ```bash
   python3 -m venv tm_env
   source tm_env/bin/activate   # Linux/macOS
   # или .\tm_env\Scripts\activate на Windows
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. Примените миграции:
   ```bash
   python manage.py migrate
   ```

5. Создайте администратора (суперпользователя):
   ```bash
   python manage.py createsuperuser
   ```

6. Запустите сервер разработки:
   ```bash
   python manage.py runserver
   ```
   Приложение откроется по адресу: `http://127.0.0.1:8000/`.

7. Запуск автоматических тестов:
   ```bash
   python manage.py test
   ```

## 🚀 Развёртывание через Docker Compose

1. Создайте файл `.env` на основе шаблона:
   ```bash
   cp .env.example .env
   ```

2. Настройте переменные в `.env`:
   - `DJANGO_SECRET_KEY` — секретный ключ Django;
   - `DJANGO_DEBUG` — режим отладки (`False` на продакшене);
   - `DJANGO_ALLOWED_HOSTS` — разрешённые домены/IP сервера;
   - `DJANGO_CSRF_TRUSTED_ORIGINS` — доверенные адреса для CSRF;
   - `APP_BIND_IP` и `APP_PORT` — IP и порт для публикации.

3. Соберите и запустите контейнеры:
   ```bash
   docker compose up -d --build
   ```

4. Создайте суперпользователя в контейнере:
   ```bash
   docker compose exec web python manage.py createsuperuser
   ```
